Four green checks. Not one of them read a signal from outside the system that produced the work.

Why now

Agents write the code.
Now they write the checks too.

Every quarter, more of the verification surface in a codebase is authored by the same class of system it is supposed to be verifying. The tests, the review, the release notes, the "done" status.

This is not an argument against agents. It is an argument that the independence of your verification has become a measurable property — and nobody is measuring it.

The insight

A check is only a check if the signal it reads comes from somewhere the thing being checked cannot write to.

this is the entire product. everything else is a consequence.

The mechanism

The write boundary

Keel walks every verification edge in a target — CI steps, test targets, review gates, deploy conditions, integration signals — and asks exactly one question about each:

What produces this signal, and can the actor being verified write to it?

Not "is this a good check". That question needs taste. This one needs a causal trace, and a causal trace can be argued about, reviewed, and got wrong out loud.

The classification

Every edge gets exactly one class

anchored

The producer sits outside the actor's write boundary. a test process exit code · a type checker · a payment that settled

self_referential

It sits inside. an LLM judging output · a doc checked against a doc · a self-set status

unknown

The fork point could not be traced. Fails closed — it counts against the ratio exactly like self_referential. absence of evidence of dependence is not evidence of independence

not_a_check

It asserts nothing at all. Excluded from the ratio — which makes it the one class worth shopping into, so it carries the same burden of argument as any other verdict. a dev server · a help target · a step that cannot fail

The number

Grounding ratio

The ratio never travels alone. The absolute anchored count and the gathered coverage print beside it, always — because a bare ratio rewards deleting checks, and the pair is the guard.

A target with zero gathered edges gets an explicit "nothing gathered" state. Never a ratio.

The economics

It gets cheaper every run

A novel shape is judged by the agent. A recurring shape gets crystallized into a probe — a small, reviewable script — so the next occurrence costs no model call at all.

Probes are code. Which means diffable, testable, rejectable — and they compound across everyone who runs Keel.

A probe may abstain. It may never return unknown. So a lazy probe degrades to ask — never to looks fine.

the mechanism ships · the library is one example probe today

illustrative — shape, not measured data

The counter-metric

And it audits itself

Probes drift. A generalization that over-matches will misclassify silently forever, and the failure is invisible precisely because it is cheap.

So Keel re-decides a sampled fraction of probe-classified nodes agentically — with the cached verdict hidden — and retires the probes that disagree.

The library's agreement rate is Keel's own counter-metric. A tool that measures groundedness while refusing to measure its own would be making the exact mistake it exists to find.

specified and built · no agreement rate yet — the library is one probe old

From a number to a path

A ratio nobody can act on is a report card

✗ Rakefile:24 tests cannot fail — Ruby's `system` does not propagate exit status, so the task exits 0 when rspec fails. → .circleci/config.yml:101 the same assertion already runs here, anchored, where CI gates on the real exit code.

illustrative shape — the routing output on the next slide is real

Independence cannot be manufactured, but it can be routed. Keel never invents an anchor — it connects a check that asserts nothing to a producer you already own. When no such producer exists, it says so instead of guessing.

Routing never moves the ratio. A proposal is not a change; the number only moves when a human applies one and Keel re-measures from the target.

The thing that proposes changes to your graph must never be the thing that scores it — so that separation is enforced by a test, not by a promise.

The output

Not a score. A ledger.

Every verdict carries the causal argument that produced it, in prose a reviewer can disagree with. The report names its own source file and revision, so the number is reproducible or it is not a number.

The second figure is a projection — what the target would measure if a human applied every route. It is arithmetic on a hypothetical. It is never written back into the ratio.

Self-contained HTML. Opens from file://. Survives being emailed.

Business model

We give away the ruler
and sell the witness.

Open source is not a concession here — it is the product's first proof. A hosted scanner that ingests your repo is one more actor with a write path into the evidence. It fails Keel's own test. Free, local and MIT is the only architecture consistent with the thesis.

You cannot self-serve independence. It is the one property you structurally cannot produce about yourself — which is exactly why someone will pay for it.

The line we will not cross

We will never sell a higher ratio

The moment the score becomes something a customer pays to improve, it becomes a selection signal — the number keeps rising while it stops meaning anything. A vendor with revenue tied to your ratio has a reason to grade you generously.

Inform freely, optimize never.
The free tier produces the same ratio as the paid one
No "upgrade to resolve your unknowns". Paid buys aggregation, private probes, and someone else's signature — never a better score.
Never phone home
No mandatory telemetry, no upload-your-repo-to-score-it. The moment Keel transmits, it becomes another actor with a write path — and the whole argument dies.
Never attest a customer we also route for
Same information set on both sides is dual-sign theater. If we propose the fix, we do not sign the report.

the business model has to obey the product's own thesis, or the product is a lie

Why this compounds

The classifier is copyable.
The library is not.

Keel is MIT and small enough to reimplement in a weekend. That is fine. What accumulates is every judged shape, crystallized into a reviewable script, contributed back by everyone who runs it — and that only accumulates where the runs happen.

The corpus is pinned to 40-character shas and deliberately spans verification cultures: generated SDKs, coding agents, mature infrastructure, a Ruby idiom, docs-heavy repos with almost no CI.

An unpinned corpus produces a number nobody can reproduce, and an unreproducible number is not a result.

Scope, honestly

What Keel does not claim

limit one

Keel measures the shape of verification, not its quality. A repo can be 100% anchored with terrible tests. Anchoring says the signal comes from outside; it does not say the signal is enough.

limit two — the deep one

A test's execution is anchored; its oracle may not be. When the same agent writes the implementation and the assertions, the runtime honestly decides pass/fail — but the specification was authored inside the write boundary, and both can drift together and stay green.

Both limits are stated in the product, in the README, and in the report itself — rather than discovered by a customer later.

A check is only a check if the signal it reads comes from somewhere the thing being checked cannot write to.

Most verification in an agent-maintained codebase fails that test. Now there is a number for how much.
