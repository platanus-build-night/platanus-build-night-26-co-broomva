The line

A check is only a check if the signal it reads comes from somewhere the thing being checked cannot write to.

Most verification in an agent-maintained codebase fails that. An LLM reviews what an LLM wrote. A status field says passed because something set it to passed. The pipeline is green and nothing has been verified.

Say it before any screen is shown. If the room does not have the sentence, the number in beat 1 is just a number.

Live, on a repo Keel has never seen — and the library grows

Somebody give me a repository. Any language, as long as it has CI.

Gather is mechanical — it locates surfaces, it does not judge them. Classification is the agent's, and every verdict ships the causal path that produced it, so you can check it in seconds without trusting me or the model. When the agent judges a shape the library did not have, it writes a probe. That probe is code: reviewable, diffable, rejectable — and the next run gets it for free.

Real output, from pallets/click. Accept 8–120 edges. Below 8, ask for another repo — see the picker below. Above ~120 the beat runs long. The volunteer repo — how to pick one in ten seconds

Beat 2 is only worth running if it is genuinely unseen, so the repo comes from the room. That means the screening rule has to be sayable while you type it.

Take it

  • Any repo with .github/workflows/*.yml — the densest source by far.
  • Python with pyproject.toml, tox.ini, pytest.ini, or conftest.py.
  • JS/TS with a package.json scripts block.
  • Anything with a Makefile, Rakefile, .circleci/, .gitlab-ci.yml, or .travis.yml.
  • Bonus texture: CODEOWNERS, .pre-commit-config.yaml, codecov.yml, dependabot.yml, or a deploy config (vercel.json, netlify.toml, fly.toml, wrangler.toml, render.yaml) — these produce review_gate and deploy_gate edges, which make a more interesting spread than CI alone.
  • Public, shallow-clonable in under ten seconds.

Steer away

  • Bazel or Buck monorepos. Gather has no BUILD/.bzl reader, so the verification lives in files it does not open. You get near-nothing and it looks like the tool failed.
  • No CI at all. Gather prints gathered 0 candidate verification edges, and a target with zero nodes is reported as "nothing gathered" — never as a ratio. Correct behaviour, terrible beat.
  • Private repos. The clone prompts for auth in front of the room.
  • Very large monorepos. Hundreds of edges runs the beat long, and the walk is depth-capped at 6 anyway.
  • A repo you have already gathered tonight. The probe library may already cover its shapes, and then nothing is minted — the beat silently loses its point.
The screening rule, stated as one sentence

Clone it shallow, run gather, and look at one number: 8 to 120 edges, take it; outside that, ask for another repo. Measured points on that scale — pallets/click 54, broomva/keel itself 32, sindresorhus/got 9, an empty directory 0.

The substrate answer — Keel's own loop, by control level

Hold this until someone asks what stops Keel from being another ungrounded loop. Every level's reference is frozen by the level above it, and the top level is frozen by design rather than by taste.

Keel loopRCS levelFrozen from below
gather + classify L0 plant output contract, the question asked
probe dispatch in sandbox, kill-timer L1 controller timeout / network policy
ε-audit (sampled, verdict-hidden, incl. agent verdicts) design — not yet shipped (W2·F). Describe the level; do not imply it ran. L2 watching loop sampling policy
schema freeze, rubric, human probe review L3 governance everything — changes rare by design

The target writes content. It never writes the question, the output contract, or the audit policy — those are frozen a level above it. That is the whole architecture in one sentence.

Cascade control's rule that the outer loop must be slower than the inner one is why L3 changes are rare rather than merely discouraged.
